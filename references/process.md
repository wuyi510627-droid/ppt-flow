# 协作流程和中间产物

## 从选题到交付

| 阶段 | 给用户看什么 | 记录位置 |
| --- | --- | --- |
| 选题 | 先确认已有主题或需要推荐。需要推荐时按选题规则提供四个具体题目，等用户明确选择或确认 | 当前主题记录 |
| 综述共读 | 综述原文、入门问题、分节阅读顺序和第一节讲解。每轮围绕概念、路线和适用条件继续读 | `materials.md` 和共读笔记 |
| 确认正式目录 | 给出正式章名、各章任务、过渡和时长，等用户确认 | `outline.md` |
| 单独确认论文清单 | 目录通过后，先列候选，再逐篇核验顶会主会发表记录和主题贴合度。给出用途、证据和取舍，用户确认后进入主讲论文共读 | `materials.md` |
| 共读主讲论文 | 逐篇讲清问题、创新、方法和实验如何验证，按用途补读对照论文。用户同意后进入逐页设计 | `materials.md` 和论文共读笔记 |
| 逐页设计 | 逐页结论、图示、例子、讲解顺序与来源。展示方法和实验两种样稿，让用户确认信息密度和版式 | `slides.md` |
| 制作与交付 | 可编辑演示文稿、逐页讲稿、必要的关键页预览。出稿前渲染复核 | PPT、演讲者备注和所需的独立讲稿 |
| 复盘 | 用户确认了哪些可复用偏好，哪些是本次案例的特殊要求 | 个人资料或用户明确要求更新的技能 |

已有 PPT 时从需要修改的环节开始。调整章节时同步目录、过渡、页码和讲稿。完整制作在主题、正式目录、论文清单、主讲论文共读结束和代表样稿这些会引起大范围返工的节点留给用户确认。已通过后按用户要求逐页审核或批量制作。用户要求批量继续时，保持已确认的样式，按每篇论文自身机制制作。输出顺序可按用户指定调整。批量制作前合并只有过渡或复述的薄页，随后核对目录、页内引用和备注时长。

主题、时长和样式等实际需要用户选择时，优先使用宿主的可点击选项。首问只显示「已有主题 / 推荐主题」，用户选择推荐后再展示四个完整候选及理由。控件容纳四项时使用一组可点选的完整题目。容纳不足时仍先展示全部候选，再用可用控件或简明回复方式收集选择。默认约 40 分钟，需要选择时给出 30、40、50 分钟。已知信息直接沿用。

## 从综述共读转到正式目录

主题明确后，先按与题目的贴合度找综述，说明选择理由及原文章节，直接读第一节。共读顺序用论文原有章节或概念标示。在同行评议或正式预印本中找不到合适综述时，说明原因，用最相关的代表资料串起同一共读环节。

每轮先用通俗的话说明原文解决的问题，再梳理主要路线、代表工作、前提和区别。用户说「继续」时沿综述读下一节。共读足以复述研究问题和路线关系后，简要回顾并询问是否进入目录阶段。只有用户明确要求出目录、同意进入该阶段或确认已共读完成，才开始整理 PPT 的章名、章节顺序和时长。用户已确认的主题只是共读的起点。

## 目录通过后确认论文清单

目录确认后，单独向用户展示材料表。每篇列出论文标题及版本、对应的章和小节、它补充的机制、对照、基线或实验细节、原文链接与章节及核对状态。按主讲、正文对照或基线、候选区分。若早期已整理过候选，按最终目录重新归位后提交确认。此时用已确认的小节名称，逐页设计时再更新到实际页码。

目录通过只确认章节结构。用户须另行确认论文清单，或在同一条消息中明确确认两项，才开始主讲论文共读。用户要求换论文时，说明要替换哪一节的证据，再提交修改后的清单。

## 核验顶会发表

正式论文清单的入选条件是已在本主题所属领域的顶会主会正式发表，适用于选入的综述、主讲和对照论文。按方向说明采用的会议口径。机器学习可查 NeurIPS、ICML、ICLR，NLP 可查 ACL、EMNLP，Web 可查 The Web Conference。用户或组会明确指定会议名单时，按该名单筛选。

先查官方论文集或会议官方发表记录，逐篇记录会议、年份、主会轨道和官方链接。以正式版本为准，有 arXiv 版本时在清单里引用正式发表记录。只查到预印本、待发表接收记录、期刊、Workshop 或 Findings 的论文不进入正式清单。无法核实主会发表的论文标为待核对，相关小节继续找符合发表要求的替代。需要引用的非顶会背景材料由用户明确同意后单列。发表门槛通过后，再做主题贴合度审查。

## 逐篇审查主题贴合度

先列按小节归位的候选论文，再展示逐篇审查结论。先用一句话写清本次的研究问题和范围，再读论文原文，核对它的实际研究问题、核心方法和相关实验设置。用一句具体的话说明「这篇在某一小节支撑哪个判断」，附原文章节或图表，并指出关键边界，例如任务不同、只有离线证据，或实验无法回答本节主张。相同术语只能作为检索线索。

审查结论使用「保留主讲」「保留为对照、基线或背景」「待核对或替换」，每篇附一句理由。只适合补背景或作对照的工作按该用途归位。证据不足时标注待核对，覆盖缺口明确后再补查。把取舍写进 `materials.md`，和候选清单一并给用户确认。增换论文时，对新候选做同样的审查。

## 清单通过后共读主讲论文

清单通过后，按已确认的目录和论文顺序开始讲第一篇。主讲论文读全文，共读时重点讲 Introduction 和 Method。每篇先用通俗语言讲它解决的问题、为什么需要这个方法、相对已有做法的创新，再沿原图、例子或公式讲清输入、机制和输出。实验部分讲任务、对照、指标和什么证据能检验主张。结果数字和输出样例按用户要求取舍。对照和基线论文按用途共读相关原文章节。

每轮交付可阅读的讲解和原文定位，记录这篇补哪一节、应该讲什么和仍有哪些疑问。共读阶段用户说「继续」时接着读未完成的章节或下一篇。用户确认共读完成或明确可以进入逐页设计后，才把笔记转成逐页内容、方法页和实验页样稿。清单审查、综述共读和助手内部的全文核对都服务于这一步的准备。

## 出片前核对正文覆盖

用材料表核对最终目录和逐页设计。每条记录至少可回答「哪篇论文、哪条路线、正文在哪一页、在支撑什么判断、核到原文哪里」。以 DOI、arXiv ID 或正式发表版本去重，区分别名相同的不同工作。标明主讲、正文对照或基线、仅书目、待核对。已读且明确归位的正文对照才和主讲计入正文覆盖。同一篇反复出现只计一次。

发现覆盖不足时，指出具体缺的是哪条路线的代表作、异机制对照、实验基线或验证依据，补查后再决定放在哪里。已有研究素材和对照若仍不足，可按实际范围和时长调整。样稿检查读者能否沿实验页复述固定什么、替换什么、比较哪组、看哪个指标。发现缺口先改材料或论证，再批量排版。

## 研究资料和个人偏好

先用用户明确指定的资料，随后查阅 `PPTFLOW_DATA`。未指定时查当前任务目录的 `ppt-flow-data/`。任务位于技能仓库内时，查仓库旁的 `ppt-flow-data/`。缺少需要的文件或只有空白选题池时，回到 `SKILL.md` 所在目录的 `assets/personal-data/`，里面有本私有仓库已同步的个人档案、选题池和主题资料。默认研究方向 PDF 位于 `assets/research/`。

用 `python scripts/init_data.py` 创建新的本地空白档案，支持 `--data-dir`，保留已有文件。研究记录和汇报草稿写到工作目录或用户指定的数据目录。用户授权同步时，更新私有仓库的相应资料。
