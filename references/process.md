# 协作流程和中间产物

## 从选题到交付

| 阶段 | 给用户看什么 | 记录位置 |
| --- | --- | --- |
| 选题 | 先确认已有主题或需要推荐。需要推荐时按选题规则提供四个具体题目，等用户明确选择或确认 | 当前主题记录 |
| 领域学习 | 综述、候选路线和初步问题边界。一起读时围绕用户不理解的概念或机制推进 | `materials.md`、初步 `outline.md` |
| 确认目录与材料 | 学术化的正式章名、各章任务、过渡、时长，列出各路线的主讲论文和对照工作，标明正文位置 | `outline.md`、`materials.md` |
| 逐页设计 | 逐页结论、图示、例子、讲解顺序与来源。展示方法和实验两种样稿，让用户确认信息密度和版式 | `slides.md` |
| 制作与交付 | 可编辑演示文稿、逐页讲稿、必要的关键页预览。出稿前渲染复核 | PPT、演讲者备注和所需的独立讲稿 |
| 复盘 | 用户确认了哪些可复用偏好，哪些是本次案例的特殊要求 | 个人资料或用户明确要求更新的技能 |

已有 PPT 时从需要修改的环节开始。调整章节时同步目录、过渡、页码和讲稿。完整制作在主题、正式目录和代表样稿这些会引起大范围返工的节点留给用户确认。已通过后按用户要求逐页审核或批量制作。用户要求批量继续时，保持已确认的样式，按每篇论文自身机制制作。输出顺序可按用户指定调整。批量制作前合并只有过渡或复述的薄页，随后核对目录、页内引用和备注时长。

主题、时长和样式等实际需要用户选择时，优先使用宿主的可点击选项。首问只显示「已有主题 / 推荐主题」，用户选择推荐后再展示四个完整候选及理由。控件容纳四项时使用一组可点选的完整题目。容纳不足时仍先展示全部候选，再用可用控件或简明回复方式收集选择。默认约 40 分钟，需要选择时给出 30、40、50 分钟。已知信息直接沿用。

## 出片前核对正文覆盖

用材料表核对最终目录和逐页设计。每条记录至少可回答「哪篇论文、哪条路线、正文在哪一页、在支撑什么判断、核到原文哪里」。以 DOI、arXiv ID 或正式发表版本去重，区分别名相同的不同工作。标明主讲、正文对照或基线、仅书目、待核对。已读且明确归位的正文对照才和主讲计入正文覆盖。同一篇反复出现只计一次。

发现覆盖不足时，指出具体缺的是哪条路线的代表作、异机制对照、实验基线或验证依据，补查后再决定放在哪里。已有研究素材和对照若仍不足，可按实际范围和时长调整。样稿检查读者能否沿实验页复述固定什么、替换什么、比较哪组、看哪个指标。发现缺口先改材料或论证，再批量排版。

## 研究资料和个人偏好

先用用户明确指定的资料，随后查阅 `PPTFLOW_DATA`。未指定时查当前任务目录的 `ppt-flow-data/`。任务位于技能仓库内时，查仓库旁的 `ppt-flow-data/`。缺少需要的文件或只有空白选题池时，回到 `SKILL.md` 所在目录的 `assets/personal-data/`，里面有本私有仓库已同步的个人档案、选题池和主题资料。默认研究方向 PDF 位于 `assets/research/`。

用 `python scripts/init_data.py` 创建新的本地空白档案，支持 `--data-dir`，保留已有文件。研究记录和汇报草稿写到工作目录或用户指定的数据目录。用户授权同步时，更新私有仓库的相应资料。
